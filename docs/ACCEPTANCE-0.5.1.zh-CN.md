## 测试准备（先做，之后不再重复）

1. **备份存档目录**：复制整个
   `%USERPROFILE%\Documents\My Games\XCOM2 War of the Chosen\XComGame\SaveData`
   到别处。这是最低成本的保险。
2. **用独立测试档**，不要用主战役档。建议另存为新档，命名为 `TRAINER-TEST`。
3. **记录本次启动参数**，确认没有 `-allowconsole`。
4. **记录启用的其他 Mod**，验收报告里要写。
5. **清空或记下 `Launch.log` 的起点**：文件在
   `%USERPROFILE%\Documents\My Games\XCOM2 War of the Chosen\XComGame\Logs\Launch.log`。
   每次操作后可直接搜 `[WOTCTrainer]`。
6. 报告里请附上每个失败项的**截图**和**该次操作前后的数值**。

风险分级含义：

| 级别 | 含义 | 对存档的影响 |
| --- | --- | --- |
| A | 只读，只观察界面，不提交任何 GameState | 不可能污染 |
| B | 战术层操作，只改当前任务状态 | 只影响本场任务；任务结束即消失 |
| C | 战略层加法写入（资源、人员、物品、治疗、属性） | 会写进存档，但都是"加东西"，可手动作废 |
| D | 战略层完成 / 退还写入（队列、退费、隐秘行动） | 会推进战役进度 |
| E | 战略层数值改写（化身计划） | 直接影响战役倒计时 |
| F | 生成士兵 / 晋升 | 永久新增或改写名册，环节最多 |
| G | 任务结束 / 重开 / 强制完成目标 | 影响任务结算与后续剧情，影响面最大 |

## A 级 —— 只读检查（零写入）

## B 级 —— 战术层操作（只影响当前任务）

> B 级全部要求：**当前是 XCOM 行动阶段、已选中一名存活的我方士兵、上一个动作已播完**。面板在 AI 回合或未选中单位时会拒绝执行（这是设计行为）。

### B1 五个战术动作
- 步骤：选中一名我方士兵 → 依次执行「恢复全部生命」「+1 行动点」「+1 移动行动点」「装填主武器」「重置技能冷却」，每次都在确认框看「原值 → 新值」后确认
- 预期：每次确认框都显示原值与新值；执行后游戏 HUD 立即可见变化（HP 回满、行动点亮起、弹匣填满、技能冷却清除）；面板「当前选择」同步刷新
- 日志：`[WOTCTrainer] Tactical unit=<ObjectID> action=<0..4>: <原值> -> <新值>`
- 存读档验证：不需要（本场任务内）；如果任务中途存档过，重新读取后应保持
- 可能污染存档：只影响本场任务；任务结束后这些改动不再有意义

### B2 无争议开关（全队无敌 / 选中士兵无敌 / 无限行动 / 无限移动 / 无限弹药 / 无需装填 / 无技能冷却 / 无限技能·物品充能）
- 步骤：逐一「开启」→ 实测效果（敌人攻击我方不掉血；同一士兵可连续行动多次；射击后弹药不减；技能无冷却；消耗品可重复使用）→ 再逐一「关闭」→ 复测效果已消失
- 预期：按钮文字在「开启」与「关闭」之间正确翻转并高亮；效果与描述一致；关闭后立刻恢复原状
- 日志：每次 `[WOTCTrainer] Tactical flag=<0..8> unit=<ObjectID>: <原> -> <新>`
- 存读档验证：不需要（除非任务中途存档并读取，则应保持开启状态）
- 可能污染存档：只影响本场任务
- **重点反例检查**：开着「无限行动」结束我方回合，观察敌方 AI 是否也能连续行动多次。敌人**不应该**继承该效果；如果敌人也无限行动，这是必须先修的缺陷
- **重点反例检查**：「全队无敌」生效时，我方士兵是否仍会因环境爆炸、坠落等非敌方伤害而受伤（按设计，无敌只挡伤不死）

### B3 命中 / 暴击 / 射击不结束回合 / 一击必杀
- 步骤：开启「100% 命中」「100% 暴击」「射击不结束回合」→ 用同一名士兵连续射击两次（验证射击后回合未结束、伤害均为暴击）→ 开启「一击必杀」→ 攻击一名满血敌人（应即死）→ 让敌人攻击我方（我方**不应**被秒杀）→ 引爆一次环境爆炸物（伤害**不应**被一击必杀影响）
- 预期：四项效果各自成立；「一击必杀」只作用于 XCOM 对敌人造成的伤害
- 日志：`Tactical flag=9` / `flag=10` / `flag=4` / `flag=11`
- 存读档验证：不需要
- 可能污染存档：只影响本场任务
- 说明：「100% 命中 / 暴击」按设计只作用于标准命中判定（StandardAim）攻击，范围伤害、近战特殊判定可能不受影响 —— 这属于已知设计边界，不算缺陷，但请如实记录观察到的例外

### B4 战斗结束后设置被清理
- 步骤：在任务中开启 3 个以上开关并确认生效 → 正常结束任务（撤离或完成）→ 回到战略层 → 进入下一场战斗 → 打开战术面板
- 预期：新战斗中 12 个开关**全部显示「关闭」**，且上一场的作弊效果**不残留**
- 日志：无（本项看的是"不该出现的行"：新战斗中不应有自动写入的 `Tactical flag=` 行）
- 存读档验证：**需要**（任务结束回战略层后存一次、退出、重读、再进下一场战斗）
- 可能污染存档：只影响本场任务 —— 本项就是用来确认这一点的；若发现效果跨任务残留，是必须先修的缺陷

## C 级 —— 战略层加法写入（会写进存档，但都是"加东西"）

> C 级全部在战略层（基地总览 / 战略地图）操作，操作前建议先手动另存一份档。

### C1 资源快捷增加与自定义数值
- 步骤：补给点 `+10` → 确认 → 再点 `+50`、`+100`、`+500`、`+1000` 各一次 → 换另一项资源（如合金）做一次 → 再对补给用「自定义数值」输入一个新总数
- 预期：每次确认框显示「原值 → 新值」且与实际累加一致；游戏内数值立即同步；重复点击正常累加
- 日志：`[WOTCTrainer] Supplies: <原> -> <新>`（资源名随所选资源变化）
- 存读档验证：**必须**（改完保存 → 退出到主菜单 → 重新读取 → 数值仍在）
- 可能污染存档：**是**（有意写入资源）

### C2 非法输入与边界
- 步骤：自定义数值分别输入 空、`-1`、`abc`、`1.5`、`2147483647`、`2147483648`；资源为 0 时输入 `0`
- 预期：非法输入被拒绝并给出中文提示，**不发生任何写入**；`2147483647` 被接受（或明确拒绝且不写入，不要溢出成负数）；`0` 在允许范围内
- 日志：被拒绝时出现 `[WOTCTrainer] Operation rejected: <原因代码>`，且**没有**对应的 `Supplies: ...` 行
- 存读档验证：不需要（本项刻意不写入）
- 可能污染存档：设计上不可能；若发现负数或溢出值进了游戏，是必须先修的缺陷

### C3 增加工程师 / 科学家
- 步骤：人员页点「+1 工程师」→ 确认 →「+1 科学家」→ 确认 → 到工程室/实验室看能否正常分配岗位
- 预期：人数 +1；面板显示新员工姓名；游戏内出现可分配的新员工；能正常分配到设施且不产生重复姓名/重复 ObjectID
- 日志：`[WOTCTrainer] <模板名>: <原> -> <新>; Added <姓名> ObjectID=<ID>`；**ObjectID 不应与既有员工重复**
- 存读档验证：**必须**
- 可能污染存档：**是**

### C4 治疗所有士兵（战略层）
- 步骤：准备至少两名**正常受伤**的士兵 → 士兵页点「治疗所有士兵」→ 确认；再点一次
- 预期：治疗项目数「原值 → 0」；受伤士兵恢复为待命；第二次点击提示「当前没有符合条件的士兵治疗项目」（不产生写入）
- 日志：`[WOTCTrainer] Healed <姓名> ObjectID=<ID> HP: <原> -> <新>`
- 存读档验证：**必须**
- 可能污染存档：**是**

### C5 士兵编辑器 —— 治疗 / 恢复意志 / 移除负面特质
- 步骤：选中一名受伤士兵 →「完全治疗 / 清除伤势」；选中一名疲劳士兵 →「恢复意志 / 解除疲劳」；选中一名有负面特质的士兵 →「移除负面特质」；每项各做一次并重复点一次
- 预期：每项都显示原值 → 新值；兵营状态同步（受伤转待命、疲劳消除）；重复点击给出「没有需要…」类提示；在医务室休养的士兵通过其自身项目完成、床位释放
- 日志：`Soldier <ID> HP: <原> -> <新>` / `Soldier <ID> Will: <原> -> <新>` / `Soldier <ID> NegativeTraits: <原> -> 0`
- 存读档验证：**必须**
- 可能污染存档：**是**
- 注意：WOTC 没有独立的"疲劳值"，疲劳由意志百分比推导，所以「恢复意志」与「消除疲劳」是同一个操作，界面已合并说明

### C6 士兵编辑器 —— 属性微调与模板默认值
- 步骤：对「命中」「移动」「闪避」「防御」各做一次 `+5` 与 `-5`；对「生命」「意志」先治疗/恢复再改上限；对任意一个基础属性点一次「模板默认值」；对「个人 AP」用「自定义数值」输入一个值
- 预期：面板值变化并写回游戏；兵营/军械库显示同步；「模板默认值」等于该角色模板的基础值（提示写明"不含晋升加成"）；AP 变化在军械库可见
- 日志：`[WOTCTrainer] Soldier <ID> field=<0..8>: <原> -> <新>`
- 存读档验证：**必须**
- 可能污染存档：**是**
- 边界：生命/移动/意志 1–1000，其余 0–1000，AP 0–100000；越界应被拒绝并提示。**未先治疗就改生命上限**应被拒绝并说明原因（否则会出现上限低于当前值的异常）
- 注意：先把数值记下来，方便改回原值

### C7 物品发放
- 步骤：分类选「武器」→ 选一件普通武器 → `+1` →「加入仓库」→ 确认 → 到军械库/仓库看；重复一次并改为 `+5`；再对一件护甲、一种弹药、一种手雷各做一次
- 预期：数量按所选数量累加（不是每次只 +1）；物品出现在军械库并可正常装备；不影响工程队列与建筑队列
- 日志：`[WOTCTrainer] Item <模板名>: <原> -> <新>`
- 存读档验证：**必须**
- 可能污染存档：**是**
- 边界：对同一件**唯一**物品重复发放时，数量应保持在 1（唯一物品不可堆叠，确认框会说明这一点）

### C8 剧情物品开关与发放
- 步骤：开启「显示剧情物品」→ 确认警告文本出现 → 发放一件剧情物品 → 关闭开关
- 预期：开启后列表变长且出现醒目警告（警告说明可能绕过战役原定获取节点）；发放走带警告的确认框；物品进入仓库；关闭后列表恢复到常规状态
- 日志：`Item <模板名>: ...`
- 存读档验证：**必须**
- 可能污染存档：**是，且风险高于 C7** —— 剧情物品可能影响战役触发，**只能在可丢弃的测试档里做**

### C9 战略面板 —— 电力与联系人容量
- 步骤：战略面板点 `+10` 电力 → 到工程室看电力条；点 `+1` 联系人 → 到战略层看联系人上限
- 预期：电力「加成」增加并反映到总电力；联系人上限增加；数值在面板上同步刷新
- 日志：`[WOTCTrainer] Avenger power bonus: <原> -> <新>` / `[WOTCTrainer] Resistance contact capacity bonus: <原> -> <新>`
- 存读档验证：**必须**
- 可能污染存档：**是**

### C10 战略面板 —— 治疗全体 / 恢复意志
- 步骤：战略面板点「治疗全部士兵」→ 确认；再点「恢复意志 / 消除疲劳」→ 确认
- 预期：受伤者恢复到待命；疲劳者意志回满、「休息中」人数减少；面板的受伤/休息计数随即刷新
- 日志：`[WOTCTrainer] Will restored for <n> soldiers`（以及治疗项的 `Healed ...` 行）
- 存读档验证：**必须**
- 可能污染存档：**是**

## E 级 —— 化身计划数值改写（直接影响战役倒计时）

### E1 化身计划 -1 / -2 / -5 / 清空
- 步骤：进战略面板，**先记下面板上四项数字**（永久值 / 设施值 / 待定值 / 总计）→ 点 `-1` 确认 → 点 `-5` 确认 → 最后点「清空化身进度」确认 → 每次确认后看结果行里的「设施扣了多少、永久扣了多少」
- 预期：
  - 总计按请求量下降（或在可扣量不足时按实际可扣量下降，结果行会显示实际分割）；
  - 结果行明确写出 设施 -N、永久 -M，两者之和等于总下降量；
  - 游戏内化身进度条随之下移；
  - 「清空」后总计为 0 或尽可能接近 0；
  - 已经没有可扣减量时提示「当前没有可扣减的化身进度」，不写入
- 日志：`[WOTCTrainer] Avatar doom: <原> -> <新> (facilities -<n>, permanent -<m>)`
- 存读档验证：**必须**（改完存档 → 重读 → 数字应保持）
- 可能污染存档：**是**（这是本清单里对战役进程影响最直接的数值改写）
- **已知的设计差异（不是缺陷，但要如实记录）**：面板的「总计」只算已结算的量，**不含正在地球上动画推进的「待定」值**。所以当地球扫描上有化身计划正在推进时，面板总计可能**低于**游戏进度条显示的格子数。请以「待定」那行解释这个差值，不要误判为写入失败
- 若发现写入后总计**上升**或**没变**，立即停止后续验收并保留该次 `Launch.log`

## F 级 —— 生成士兵与晋升（永久改动名册，环节最多）

> F 级每个子项都用一个新的测试存档分支做，做完一档存一次，避免一个问题污染后面的判断。
> 本版本**不做**"复制已有单位"、也不直接写高军衔，全部走原版创建与逐级晋升流程。

### F1 生成士兵 —— 随机新兵
- 步骤：危险功能面板 →「职业」循环到「新兵」→「数量」输入 `1` →「生成士兵…」→ 确认
- 预期：兵营 +1；新兵有合法姓名、昵称、国籍、外观；在兵营可查看、可装备、可参加任务；**不出现重复 ObjectID**
- 日志：`[WOTCTrainer] Added <职业> <姓名> ObjectID=<ID> Rank=<n>`、`[WOTCTrainer] Barracks: <原> -> <新>`
- 存读档验证：**必须**
- 可能污染存档：**是**

### F2 生成士兵 —— 指定职业（低军衔）
- 步骤：「职业」循环到「游侠」→「军衔」选到列兵 → 生成 1 名；再对「专家」做一次
- 预期：兵营出现对应职业；可以正常装备该职业武器；技能树正常（列兵只有一级技能可选择）
- 日志：同 F1
- 存读档验证：**必须**
- 可能污染存档：**是**
- 边界：数量输入 `0`、`21`、字母应被拒绝；一次生成 20 名应能完成且兵营计数正确

### F3 生成士兵 —— 高军衔（逐级晋升路径）
- 步骤：「职业」=专家 →「军衔」选到上尉 → 生成 1 名 → 到军械库检查这名士兵的每一级技能是否可以选择
- 预期：士兵按原版晋升流程逐级提升到目标军衔；军械库能看到每一级对应的技能/AP 选择；面板与兵营显示一致
- 日志：`Added ... Rank=<目标军衔>`
- 存读档验证：**必须**
- 可能污染存档：**是**
- **本项是 F 级里最需要仔细看的**：如果出现"军衔对了但技能树缺级 / AP 不对 / 无法选技能"，请截图并保留 `Launch.log` —— 这类不一致会让该士兵无法正常使用

### F4 生成士兵 —— 派系士兵
- 步骤：在一个**已接触对应派系**的存档中生成 死神 / 散兵 / 圣殿骑士 各 1 名；再在一个尚未接触派系的存档中尝试生成
- 预期：已接触派系的可以正常生成并出现在兵营；未接触派系的被拒绝并提示「请先在战役中接触对应抵抗派系，再添加该派系士兵。」
- 日志：成功时 `Added ...`；被拒绝时 `[WOTCTrainer] Operation rejected: FactionLocked`
- 存读档验证：**必须**
- 可能污染存档：**是**

### F5 逐级晋升（对已有士兵）
- 步骤：士兵编辑器里选中一名士兵 →「军衔 / 新兵职业…」→ 进入危险功能面板 → 设「目标军衔」→「逐级晋升…」→ 确认
- 预期：军衔提升到目标；到军械库能选择新增等级的技能；面板与兵营同步
- 日志：`[WOTCTrainer] Soldier <ID> Rank: <原> -> <新> Class=<职业>`
- 存读档验证：**必须**
- 可能污染存档：**是**
- 说明：**新兵**在晋升时可以一并选择四个普通职业之一；**已晋升士兵的转职与降级按设计保持禁用**，界面上有原因说明，不要尝试绕过

## G 级 —— 任务结束、重开与强制完成目标（影响面最大）

> G 级全部要求：单机战术战斗、非教学任务、XCOM 行动阶段。建议每一项都在刚保存过的存档上做。

### G1 完成选中的目标记录（含你之前遇到的"中继器已毁但清扫未结算"场景）
- 步骤：
  1. 先在面板**左侧**找到与「清扫 / 消灭全部敌对目标」语义对应的那条内部记录，把它的名字抄下来；
  2. 再看**右侧**「HUD 目标状态」，确认哪一条还挂着；
  3. 点中左侧那一条 →「完成选中目标记录…」→ 确认；
  4. 回到面板点「刷新任务目标显示」。
- 预期：内部记录变成 `[X]`；右侧 HUD 列表里对应目标变为已完成或消失；任务的结算条件随之推进
- 日志：`[WOTCTrainer] Objective <内部ID>: incomplete -> completed`
- 存读档验证：**必须**
- 可能污染存档：**是**
- **重要**：面板**不会**把左侧第 N 行等于右侧第 N 行。两边的数据结构在原版里没有可靠的一一对应关系，所以请用名字而不是行号去对应。如果实在找不到能推进结算的那一条，**不要反复点**，把左右两侧的截图发来
- 结束本项前请再确认一次：结算是否真的推进了（撤离点开启 / 任务可以结束）。**只把 `[X]` 打上但结算没动，也是需要修的缺陷**，请如实记录

### G2 跳过当前 AI 回合
- 步骤：结束我方回合 → 等 AI 回合开始（能看到 AI 在动）→ 战术面板 →「任务」→「跳过当前 AI 回合…」→ 确认
- 预期：AI 回合立即结束，控制权回到 XCOM；不会卡住
- 日志：`[WOTCTrainer] AI player=<ID>: active turn -> skip requested`
- 存读档验证：**必须**
- 可能污染存档：**是**
- 说明：在**我方**回合或 AI 没有真正轮到时点它，会提示「仅在单机战术的 XCOM 行动阶段可用…」类错误，这属于设计行为

### G3 禁用 / 恢复 AI 行动规划
- 步骤：战术面板 →「任务」→「禁用 AI 行动规划…」→ 确认 → 让敌方回合跑一次 → 再点「恢复 AI 行动规划…」→ 确认
- 预期：禁用期间 AI 不执行行动（回合可能停住不结束）；恢复后 AI 恢复正常行动
- 日志：`[WOTCTrainer] AI turn control: disabled on <n> AI player(s)` / `AI turn control: restored on <n> AI player(s)`
- 存读档验证：**必须**
- 可能污染存档：**是**
- **兜底**：如果禁用后卡在 AI 回合无法恢复，用 G2「跳过当前 AI 回合」脱困；仍不行则读取本项操作前的存档
- 诊断面板里的「AI Hang 范围」一行会显示外星人与失落者两方当前的 开启/关闭 状态，用来确认是否已恢复

### G4 完成全部未完成目标记录
- 步骤：任务进行中 → 战术面板 →「危险功能」→「完成全部未完成目标记录…」→ 确认
- 预期：内部记录全部变为 `[X]`；任务按原版流程结算（撤离点开启 / 可结束）
- 日志：`Objective <内部ID>: incomplete -> completed`（多条）
- 存读档验证：**必须**
- 可能污染存档：**是**
- 说明：本功能**只完成记录**，不会替你去触发任务脚本里的其他条件。若结算仍未推进，请记录并报告

### G5 按胜利结束任务
- 步骤：战术面板 →「危险功能」→「按胜利结束任务…」→ 确认
- 预期：
  - 如果任务的胜利条件**已经满足**：走原版 `EndBattle` 流程结束任务、播放结算、回到战略层，战役可正常继续；
  - 如果胜利条件**尚未满足**：被**拒绝**并提示需要先完成目标（这是刻意设计：不允许跳过任务状态直接判胜）。此时可先用 G1 / G4 完成任务记录，再回来点
- 日志：`[WOTCTrainer] Mission: active -> requested victory via EndBattle`
- 存读档验证：**必须**（结束后存一次、退出、重读，确认战役可继续、士兵状态与奖励正常）
- 可能污染存档：**是**（本清单中影响面最大的一项）

### G6 按失败结束任务
- 步骤：在另一场任务中 →「按失败结束任务…」→ 确认
- 预期：按原版流程以失败结束，出现相应结算（可能损失士兵或任务奖励），回到战略层后可继续
- 日志：`[WOTCTrainer] Mission: active -> requested failure via EndBattle`
- 存读档验证：**必须**
- 可能污染存档：**是**
- 说明：请在一场**可以接受失败**的任务上做，例如已经打算放弃的游击行动

### G7 重开当前任务
- 步骤：战斗中 → 任务面板 →「重开当前任务…」→ 确认
- 预期：任务按原版流程重新载入，本场进度清零；铁人模式与教学任务会被**拒绝**并提示不支持
- 日志：`[WOTCTrainer] Mission: current progress -> restart requested`
- 存读档验证：**必须**
- 可能污染存档：**是**
- 说明：「同种子重开」按设计保持**禁用**（SDK 侧无法证明能复现同一战场），界面上已说明原因

### A.3 按设计保持禁用、因此**无法**验收的功能

这些不是"没做"，而是"刻意不做"，界面上都写了原因，看到灰显按钮即为预期：

| 功能 | 禁用原因 |
| --- | --- |
| 降级 | SDK 的调试重置流程未完整处理 WOTC 已花费 AP 与持久能力 |
| 已晋升士兵的转职 | 同上 |
| 复活阵亡士兵（战略层与战术层） | 无法保证 roster / 战术单位 / 背包 / 任务状态四者一致，不做假复活 |
| 传送 | 尚未实现（Phase 6 范围）。当前界面复用了「该功能当前版本不安全，已禁用。」这句文案，实际原因是还没做，不是判定为不安全 |
| 同种子重开 | 原版 `RestartLevelWithSameSeed` 依赖 native 实现，源码里核对不到，无法证明能复现同一战场 |
| 强制全队撤离 | 找不到能保证结算一致的 API |

### A.4 尚未实现的功能（与需求文档相比）

- **显示全图 / 迷雾开关**：战术面板里没有这两项。
- **冻结敌方 AI**：已经能用，但位置在「任务」面板的「禁用 AI 行动规划 / 恢复 AI 行动规划」，**不在**战术面板的 12 个开关里；它是持续生效的开关（不恢复就一直生效），作用于外星人与失落者两方。
- **需求文档第五节的 "Instant … ON/OFF" 开关**：做成了「立即完成」这类一次性操作，**不是**常驻开关。原因已记录在 `docs/API-AUDIT.md`：战略层没有可供 Mod 挂载的逐 tick 钩子，游戏内的 `setstrategyfacilitiesfree` / `instantbuild` 两个开关在 SDK 源码里没有任何读取点。
- **需求文档第六节的 "Add 1 / Add 5 / Add 10"**：做成数量步进 + 发放，步进档位为 `+1 +5 +10 +50 +100 +500`，覆盖了原来的三档。

## 附录 B：通过标准

一个级别要算通过，必须同时满足：

1. 该级别所有子项的"预期结果"都出现；
2. 每一项都完成了清单里要求的**保存 / 重新读档**验证，且读档后数值与状态保持一致；
3. `Launch.log` 里除了 `[WOTCTrainer]` 行之外，**没有**新增的 `Error`、`Accessed None`、`ScriptWarning`、`Assertion failed`，尤其是没有 `[WOTCTrainer] ... verification failed`；
4. 没有出现需要"用另一个作弊功能去补救"的情况。

任何一条不满足，就把该项记下来，先不要进入下一级。
